# مسیر بررسی ۳۰ پلتفرم بدون feed معتبر

هدف، دستیابی قانونی و پایدار به quote read-only است؛ نه دورزدن احراز هویت یا محدودیت دسترسی.

## کشف ثبت‌شده: گلدیس

کلاینت عمومی گلدیس در ماژول `priceStore` آدرس زیر را فراخوانی می‌کند:

```text
GET https://goldis.ir/price/api/v1/price/assets/gold18k/final-prices
```

پاسخ شامل `final_buy_price`، `final_sell_price` و زمان جلالی است. قیمت‌ها ریال/گرم هستند و در اپ بر ۱۰ تقسیم می‌شوند. تا تأیید شمول fee و تبدیل timestamp به UTC، quote فقط نمایش داده می‌شود و وارد سیگنال نمی‌شود.

## A — کشف عمومی

- بررسی HTML/SSR و داده‌های hydration
- جست‌وجوی XHR، GraphQL، SSE، WebSocket و Socket.IO در کلاینت عمومی
- ثبت schema، واحد، timestamp، جهت و rate limit
- تطبیق پاسخ با عدد UI و سپس preview سفارش

## B — اپ رسمی روی دستگاه خودمان

- بررسی deep-link و endpointهای pre-order در یک حساب آزمایشی متعلق به خودمان
- ثبت نرخ خرید و فروش نهایی بدون ارسال سفارش
- عدم pin-bypass، عدم استخراج credential و عدم خودکارسازی خلاف شرایط استفاده

## C — تشخیص white-label

چند برند ممکن است از تأمین‌کننده و موتور قیمت مشترک استفاده کنند. کشف backend مشترک هزینهٔ فنی را کم می‌کند، اما تا زمانی که موجودی و اجرای مستقل اثبات نشود آن برند یک venue مستقل برای آربیتراژ محسوب نمی‌شود.

## D — API رسمی یا قراردادی

برای پلتفرم‌های بسته، درخواست باید مشخصاً شامل این موارد باشد:

- endpoint read-only برای bid/ask نهایی مشتری
- timestamp سرور و TTL قیمت
- schema نسخه‌دار و sandbox
- rate limit و سیاست polling
- جدول fee، VAT، حداقل سفارش و زمان تسویه
- اجازهٔ ذخیره، تحلیل و نمایش داده

## خروجی هر بررسی

هر پلتفرم باید با یکی از نتایج زیر بسته شود: feed معتبر، reference-only، نیازمند partner API، white-label غیرمستقل، یا خارج از دامنه. تا تکمیل تمام ستون‌های صحت داده، آن پلتفرم وارد موتور سیگنال نمی‌شود.
